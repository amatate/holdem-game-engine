# 2–6 人牌桌与自动 NPC 阵容设计规格

日期：2026-08-30
状态：待用户书面审核

## 1. 目标

把当前固定四人终端比赛扩展为玩家可选择 2–6 人桌的纯德州扑克模式。玩家只选择人数，不逐个挑选对手；系统从角色目录中自动、无重复地组成 NPC 阵容。

本阶段同时新增三名仍由参数驱动的纯德州角色，用于扩大牌风覆盖面。它不包含作弊能力、动态学习、浏览器牌桌或完整 TUI。

## 2. 已确认的产品决策

- 牌桌人数表示初始参与人数，可选 2、3、4、5、6。
- 所有座位开局均有人，不支持“六人桌只坐四人”的初始空座。
- 人类玩家固定在物理座位 0。
- 玩家只选择人数；NPC 由系统自动安排，不提供逐个选择界面。
- NPC 阵容必须无重复。
- 相同人数和角色目录版本产生相同阵容；`runSeed` 不参与选人。
- 纯德州规则、筹码、发牌、行动、结算、回放和隐藏信息边界保持不变。
- 当前默认四人桌不再是规则假设，只是人数选择中的一个选项。

## 3. 当前基础与改动边界

规则核心已经支持 2–6 人、HU 特例、固定物理座位和 2–6 人随机手牌回归。本阶段不修改：

- `TournamentConfig` 的规则含义。
- 按钮、盲注、行动顺序、合法动作或结算算法。
- `TournamentState`、领域事件或回放格式。
- `PlayerObservationV1` 和 AI 隐藏信息投影。

主要改动位于：

- CLI 选项与启动提问。
- 角色目录、自动阵容选择器和 Participant 工厂。
- CLI、角色行为和 2–6 人完整锦标赛测试。

若实施过程中必须修改上述规则核心或事件格式，应停止并升级设计，不把它混入本阶段。

## 4. CLI 体验

### 4.1 命令行参数

增加可选参数：

```text
--players <2|3|4|5|6>
```

`--seed` 与 `--players` 可按任意顺序出现，各自最多一次。非法人数、缺值、小数、非数字或重复参数直接给出中文错误，不做静默截断或回退。

示例：

```bash
npm run play -- --players 6 --seed demo-6p
```

### 4.2 交互选择

未提供 `--players` 时，在比赛开始前询问：

```text
请选择牌桌人数（2-6，直接回车默认 4）：
```

- 空输入选择 4。
- 输入 2–6 的整数后继续。
- 其他输入显示具体错误并重新询问，不重建随机种子或 Prompt。

确定人数与阵容后，先展示本局种子，再展示本桌对手名单，然后进入现有比赛流程。

### 4.3 CLI Runtime

人数选择继续通过现有可注入 `CliPrompt` 完成，测试不得读取真实 stdin 或等待真实时间。`--players` 存在时不询问人数，但仍创建比赛中人类行动所需的 Prompt。

## 5. 自动阵容选择

新增纯函数：

```ts
selectNpcRoster(playerCount: number): readonly CharacterId[]
```

规则：

1. 校验人数为 2–6，并返回恰好 `playerCount - 1` 个不同角色。
2. 使用按人数维护的只读阵容表，不读取对象键枚举顺序或随机数。
3. 四人桌保留当前“猎手、疯狗、跟注站”组合。
4. 其他人数采用策划过的固定组合，让新增角色在不同人数中实际出场。
5. 选人不得消费洗牌、AI 决策、权益采样或下注尺寸随机流；改变阵容表视为明确的产品版本变更。
6. 阵容结果不是规则核心状态，也不进入 `TournamentConfig`；实际 `playerId` 仍通过 participant 列表写入比赛事件，所以回放可看到真实参赛名单。

首版固定阵容：

| 总人数 | 自动 NPC 阵容 |
| --- | --- |
| 2 | 猎手 |
| 3 | 小刀、跟注站 |
| 4 | 猎手、疯狗、跟注站 |
| 5 | 岩石、猎手、小刀、重锤 |
| 6 | 岩石、猎手、疯狗、伏蛇、重锤 |

座位分配：

- 座位 0：人类玩家“你”。
- 座位 1 至 N−1：按选择器返回顺序放置 NPC。

CLI 在发起比赛前公开显示角色姓名和绰号，不公开 AI 参数。

## 6. 角色目录与新角色

### 6.1 目录维护

新增：

```ts
export const CHARACTER_IDS = [
  'rock',
  'hunter',
  'maniac',
  'calling-station',
  'small-ball',
  'trapper',
  'value-bettor',
] as const;
export type CharacterId = typeof CHARACTER_IDS[number];
```

运行时 ID 校验、`CharacterId` 类型和自动阵容选择都从同一列表派生，避免 union、guard、catalog 三处手工同步。

新增 `createCharacterParticipant(characterId)`，统一使用 `CharacterDefinition.displayName`、`nickname` 与 profile 创建 `AgentParticipant`。CLI 不再手工重复角色姓名。

角色定义仍只包含展示身份和 `StyleProfile`，不增加角色能力、记忆或隐藏规则。Factory 的公开返回类型使用 `PokerAgent`/`Participant` 边界，不要求调用者依赖具体 Agent 类。

### 6.2 新角色目标

首版新增以下三名纯参数角色；姓名、绰号和牌风约束都属于本阶段交付内容：

#### 程墨“小刀”——小球诈唬者

- 中等入池率，中高诈唬与进攻。
- 高位置意识。
- 主要使用半池、小幅变化的下注。
- 超池频率明显低于“疯狗”。
- 与“猎手”的区别是更多小额试探、较少重压。

#### 苏蔓“伏蛇”——陷阱手

- 中等偏紧、低诈唬、低波动。
- 当前目录中最高的强牌慢打倾向。
- 面对合理下注有一定黏性，但不达到“跟注站”的极端水平。
- 主要验证 `slowPlay` 参数轴。

#### 韩烈“重锤”——价值下注者

- 中等偏紧、高主动进攻、低诈唬。
- 偏好满池价值下注，偶尔超池。
- 风险偏好高于“岩石”、低于“疯狗”。
- 与“猎手”的区别是更少位置诈唬、更重视强牌大额取值。

实现中的具体参数必须满足现有 `[0,1]` 约束，并通过相对行为基准验证上述差异；不以某一个随机 seed 的单次行动作为角色验收。

## 7. 数据流

```text
CLI argv / 人数提问
        ↓
playerCount ──→ selectNpcRoster ──→ NPC CharacterIds
runSeed ──────────────────────────→ Tournament Controller
                         ↓
HumanParticipant + createCharacterParticipant(...)
        ↓
TournamentConfig { maxSeats: playerCount }
        ↓
现有 runTournament / rules core / public projection
```

初始筹码、盲注等级、按钮位置和升级节奏沿用当前配置，只复制配置并覆盖 `maxSeats`；不得直接修改冻结的默认配置对象。

## 8. 错误处理

- CLI 参数错误：启动比赛前失败，错误信息不得包含完整牌堆或私密状态。
- 交互人数错误：原地重新询问。
- 角色目录不足、重复 ID 或未知 ID：视为开发配置错误，启动前抛错，不使用重复 NPC 兜底。
- 自动选择器不得读取时间、`Math.random()` 或全局可变状态。
- 角色 Agent 若返回非法扑克行动，继续沿用当前 controller fallback 策略。

## 9. 测试与验收

### 9.1 人数与参数

- `--players 2`、`4`、`6` 正确解析，且可与 `--seed` 交换顺序。
- 缺值、1、7、小数、非数字和重复 `--players` 被拒绝。
- 无参数时空输入选择 4；非法交互输入后可重新输入合法值。

### 9.2 阵容

- 2–6 人分别返回 1–5 名不同 NPC。
- 每个人数都精确匹配规格中的固定阵容。
- 改变比赛 seed 不改变同一人数的 NPC 阵容。
- 角色选择不调用任何随机源，因此不会改变比赛 seed 的洗牌流定义。
- Participant 的 `playerId` 来自角色目录，不再由 CLI 手写。

### 9.3 角色行为

- 原四名角色的现有风格基准保持通过。
- 小刀相对疯狗使用更小尺寸、较少超池；相对岩石有更多诈唬。
- 伏蛇在强牌场景的慢打率高于所有现有角色。
- 重锤在价值场景比岩石更常主动大额下注，垃圾牌诈唬率低于猎手。
- 每项统计必须使用固定样本矩阵与分母下限，不能由一两次随机行动证明。

### 9.4 完整比赛

- 2、3、4、5、6 人各至少完成一场固定种子的完整锦标赛。
- 每场有限步内结束、总筹码守恒、事件可重放、隐藏信息不泄漏。
- CLI 六人 smoke 显示六个连续物理座位与五名不同 NPC。
- 现有 100 手 2–6 人规则回归和所有 classic 测试继续通过。

## 10. 非目标

- 手动选择、替换或锁定某个 NPC。
- 初始空座、真人多人或联网匹配。
- 角色长期记忆、学习玩家、情绪和关系系统。
- 作弊能力、特殊规则或角色被动技能。
- 浏览器牌桌、美术、头像、动画和音效。
- 全屏终端 TUI；除人数选择与名单展示外，CLI 视觉优化另立阶段。

## 11. 完成标准

本阶段完成需要同时满足：

1. 玩家可通过参数或启动提问选择 2–6 人。
2. 系统自动生成无重复、可复现的 NPC 阵容。
3. 新增三名可由统计区分的参数角色。
4. 2–6 人完整锦标赛全部结束且规则、筹码、回放和隐私断言通过。
5. 经典纯德州行为未被能力或 UI 逻辑污染。
