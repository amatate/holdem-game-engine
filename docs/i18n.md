# Browser localization

The browser has Chinese and English display modes. Entry links accept `?lang=zh` or `?lang=en`. Precedence: recognized query parameter → saved `holdem.locale` preference → browser language. The selector updates the query parameter and preference. Both Node and Pages load the same code.

## Boundary

- `i18n-catalog.ts` contains curated literal messages and constrained numeric templates. NPC English names are presentation aliases, not changes to roster identity.
- `i18n.ts` projects canonical Chinese DOM text to English. Original text is retained per node, so switching back restores the exact source.
- Only text nodes and allowlisted human-readable attributes (`aria-label`, `title`, `placeholder`, `alt`, description metadata) are changed. Script/style/textarea contents and `data-no-i18n` regions are excluded.
- IDs, command values, data attributes, card identities, numeric inputs, game packets, saves, and RNG state are untouched. No HTML is constructed from translations. Switching makes no game API request and does not recreate controls.
- Every client render/lock and status-message update refreshes the projection. Playback continues on the same timeline, and drafts/focus remain in their original controls.
- This is not an API/CLI translation layer. Protocol values, internal errors, and diagnostic logs keep their canonical language.

## Adding messages

Add the full source sentence and natural English wording to the catalog. Prefer full phrases over fragments, especially where English needs different word order. Numeric templates use `{0}`, `{1}`, etc.; slots accept signed numeric values, not arbitrary strings. Longer source matches take priority. Unknown text is preserved rather than guessed.

For composed text, check spaces and grammar around names/numbers. Exact-source tests alone cannot evaluate fluency. Keep card symbols and poker distinctions (call amount vs. raise-to total, main pot vs. side pot) intact.

Run `tests/web/i18n.test.ts` for catalog consistency and real-engine traversal of Classic 2–6 players, ability results, three tutorials, and quiet/warm/direct story branches. The fixtures check visible text/labels, state immutability, and hidden-card boundaries. They are not proof of every random dialogue combination or browser layout.

## Browser acceptance

Verify the homepage and all game controls in English, then:

1. Type a non-default raise, switch Chinese → English → Chinese, and check the amount, hand, pot, stacks, and legal actions do not change.
2. Switch during playback; reach the same decision/settlement without duplicate actions.
3. Test tutorial guidance, public speech/observations, ability confirmation/private intel, and settled save/restore.
4. Check desktop and narrow-screen controls, long NPC labels, help text, and no horizontal overflow. Check the browser console.
5. Verify a deployed `?lang=en` link after Pages completes; a local preview alone is not deployment evidence.

## Saves

Language is independent from checkpoints. The existing strict build fingerprint is deliberately unchanged as a policy: a new build may reject an older save even when only display code changed. The warning preserves old data until a new table settles; this feature does not silently migrate or delete it.
