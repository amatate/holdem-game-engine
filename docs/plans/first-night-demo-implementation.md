# 第一夜章节 Demo 实施和验收计划

日期：2026-10-26。执行范围以[开发规格](first-night-demo-design.md)为准；完整故事方向见[主线草案](night-table-story-outline.md)。开发前计划保留如下；本地实现与验收证据见文末记录，不以计划条目充当完成证明。

## 当前系统和需要补齐的部分

| 当前代码 | 已有能力 | 本章需要补齐 |
| --- | --- | --- |
| `src/game/game-session.ts` | 真实扑克、决策边界、三种能力和单桌次数 | 保持为单桌规则权威，由章节层调用 |
| `src/game/living-table.ts` | 六手序章、公开事件、关系回应 | 新章节独立编排，不把六手上限改成全局行为 |
| `src/game/tutorial.ts` | 三关真实规则教学 | 开章前可进入，完成后回到章节准备 |
| `src/web/table-session.ts` | NPC 阵容、桌面投影、记忆与回顾 | 支持章节指定阵容和受约束的单桌结束 |
| `src/web/server.ts`、`browser-api.ts` | Node 和浏览器两套请求宿主 | 共用章节命令处理，不各写一套流程 |
| `src/web/checkpoint-data.ts`、`checkpoints.ts`、`browser-store.ts` | 结算点、日志重放、摘要核对 | 章节独立槽、桌间检查点和跨桌重放 |
| `src/web/experience-render.ts`、`client.ts` | 玩法入口、教学和剧情显示 | 开章准备、歇桌、章节笔记与结尾 |
| `src/web/i18n-catalog.ts` | 中英文文本转换 | 所有新文本及动态战绩的英文表达 |

当前自由桌按人数自动选择固定阵容；两人桌默认是林岚，不能直接拿它冒充莫叔的第一桌。章节必须显式配置阵容，并保持座位身份、发言人物和策略实例一致。

当前每个本地会话只有一套引擎 handle 与动作日志。三桌切换需要保留章节状态并创建下一桌引擎，不能只换人物立绘、清零筹码或在界面上改手数。

## 实施约束

新增章节状态独立于规则核心，拟放在 `src/game/first-night.ts`。章节控制当前桌次、精力、选择、笔记和结尾；每一桌的发牌、合法动作和筹码由现有 GameSession 计算。

新增 Node 与浏览器共用的章节宿主适配，拟放在 `src/web/first-night-session.ts`。它负责开桌、将已接受结果写回章节、限手收尾与下一桌准备；只在真实结算后允许切换。采用同一组指令与验证规则接入两种宿主。

能力消耗须在同一条宿主操作中完成：校验章节能力与预算，提交现有能力命令，只有接受后才扣精力并写入一次日志。向客户端投影章节能力可用状态；只隐藏按钮不足以限制请求。

章节指令带预期章节修订号，扑克指令保留现有 packet 与 decision 校验。换桌产生新的桌面身份，上一桌的请求不能在下一桌被接受。人物以角色身份跟踪关系，以桌次和手数共同标记记忆。

沿用现有资产，以本晚记分纸呈现真实战绩。新美术只在现有资产无法表达关键场景时提出；首版不依赖在线语言模型或新的外部服务。

## 实施里程碑

### M1 三桌章节流程

交付可从主页完整游玩的普通路线：章节准备、莫叔四手桌、四人六手桌、可选的林岚六手桌、两次桌间停留和散场。第二桌后离开属于完整分支。先接入正式人物策略和现有立绘，不以教学对手替代。

散场后追加几天后的邀约消息和玩家回应，保存询问、拒绝或以后再说的结果。本 Demo 不接入大桌经济，不把询问视作接受引荐。三次人际揭露属于后续完整游戏内容，不在第一夜强行触发。

结算或提前歇桌后生成一次本桌战绩。主角或对手提前淘汰时仍可进入合适的桌间回应；下一桌按明确的开桌规则创建新引擎。笔记记录已发生的公开交锋，不追加前稿的赠筹线索。

验收普通完成、首桌淘汰、末桌失利、持平、主动离桌、重复点击和旧桌请求。实际结算与记录必须一致；桌间选择不可重复领取效果。

### M2 暗手选择和人物连续性

加入三种开章能力选择、精力预算、两次休息或交谈，以及成功使用后才扣预算。根据[对白试稿](first-night-dialogue-draft.md)逐段接入场景；先验收开场和一段真实交锋的语气，再扩写。前稿的记分纸解谜与赠筹结尾不进入代码。

复用现有角色战术和情绪逻辑，补齐跨桌的公开行动记忆。对未在场的角色只保留他实际看到的事件；私有能力信息不写进人物记忆或对白。

验收三种能力的成功、失败、耗尽、过期和重复请求；桌间恢复封顶；关闭暗手的普通路线；莫叔、阿凯、林岚的公开观察差异。需要验证真实行动，不以配置值或台词存在作为角色风格验收。

### M3 存档和实际界面

增加独立章节槽以及准备、结算、桌间、结尾检查点。将初始设置、每桌动作与章节选择组成有顺序的记录，恢复时校验桌次、预算、战绩与最终摘要。

完成本晚记分纸、章节条、桌间页、中英文和窄屏布局。过场等待事件播放，允许跳过呈现；牌局结算与玩家选择保持一次生效。

通过 Node 重启和浏览器重载恢复测试后，再做桌面与手机视口实玩。确认普通自由桌的存档保持可用，开章不会静默覆盖原存档。

### M4 试玩构建和反馈修改

产出带明确版本号的本地构建与浏览器试玩构建，附已知问题和实际玩法截图。先在独立测试地址验收，再按发布请求更新线上版本。

邀请陌生玩家前完成一次完整普通路线和三种暗手路线的人工走查。试玩后按阻塞、理解、节奏、人物、重玩动机排序修改。根据实测决定是否调整 16 手上限、多人桌人数和能力预算。

## 关键验收矩阵

| 场景 | 检查重点 | 方法 |
| --- | --- | --- |
| 正常走完三桌 | 人物、桌次、场景和散场顺序一致 | 章节状态测试与浏览器实玩 |
| 拒绝第三桌 | 正常散场，不强制重试，不伪造第三桌战绩 | 章节分支和恢复测试 |
| 散场后收到新邀约 | 时间切换清楚；询问或拒绝均不扣款、不自动入桌，恢复不重复消息 | 剧情分支和恢复测试 |
| 一手提前全下淘汰 | 本手正确结算，再进入本桌收尾 | 固定种子回放及真实操作 |
| 达到手数上限 | 不多发下一手，不冒称锦标赛冠军 | 状态边界和宿主集成测试 |
| 跟注不足、全下、边池 | 现有筹码规则保持，战绩用真实净结果 | 现有核心回归和章节结果核对 |
| 能力失败或重复 | 预算、次数和核心状态均不重复改变 | 章节与能力宿主集成测试 |
| 两次桌间选择 | 每次只能选择一次，恢复精力封顶 | 修订号、重复请求与恢复测试 |
| NPC 不在场 | 不获得别桌动作或私有能力信息 | 角色身份和公开事件测试 |
| 换桌后收到旧请求 | 不下注、不扣精力、不跳过新桌 | 旧桌身份及过期 packet 测试 |
| 退出后继续 | 恢复到明确边界，无重复奖励和剧情 | Node 重启与浏览器重载 |
| 当前手未完成时退出 | 上次检查点保留，主页准确说明 | 实际关闭并恢复 |
| 损坏或旧版章节存档 | 不误加载，不静默删除 | 存储错误测试 |
| 章节与自由桌分别续玩 | 两个槽互不覆盖 | 两种宿主集成和实玩 |
| 切换语言和调整速度 | 状态不变，动态文案完整，顺序正确 | 中英文及倍速实玩 |
| 1280×720、1366×768、390px | 主要操作可见，气泡不挡牌和按钮 | 页面截图与元素边界检查 |

测试优先覆盖状态和金额的实际风险，沿用现有核心回归。测试通过后，仅在新改动或失败产生新疑点时重复相应检查；牌力评测不是本章的交付门槛。

## 首次试玩记录

建议招募 8–12 人，至少覆盖首次接触德州和已经会打的玩家。每人先独立操作，观察者只在无法继续时协助；记录发生时间和卡住的位置。

每人保留一张简短记录：

- 是否理解自己为什么来到这里；何时独立完成第一次有效行动。
- 教学、开章、每桌、歇桌和结尾的用时，以及未完成的退出位置。
- 混淆过的按钮、金额或牌型；是否因为误解而进行意外下注。
- 是否注意到不同 NPC 的打法，并能举出一手具体例子。
- 暗手何时使用或保留；精力和桌间选择是否能理解。
- 是否愿意接人物的话，是否主动选择留下单挑；最记得的人物和具体交锋。
- 是否自愿继续自由桌或重玩另一条路线；具体想体验什么。
- 是否愿意接受阿凯的新邀约，或想先问清哪一件事；不提前揭露背叛来引导回答。

以下是修改目标，不是已经达到的指标：多数新手能独立完成教学并开始第一桌；玩家能辨认至少两位人物并说出一段具体交锋；暗手路线存在真实的使用或保留选择；没有因错误存档、失效按钮或金额展示而退出。小样本只用于发现问题，不推算销量或留存率。

## 开发前审阅和交付边界

先确认开发规格末尾的三项产品选择，再接入剧情和章节状态。每个里程碑提供可以实际体验的版本及相应验证记录，不等全部内容完成才展示。

## 本地实现记录 · 2026-10-26

M1–M3 的可玩流程已接入 Node 宿主与浏览器 Worker：

- 主页准备 → 莫叔两人桌（最多四手）→ 阿凯和林岚到场 → 四人桌（最多六手）→ 可选林岚单挑（最多六手）→ 散场 → 几天后的邀约及回应。
- 每桌创建新引擎、固定 1/2 盲注、每人重新买入 100。手数到限或有人使本桌无法继续时，先保留真实结算再收尾；可在结算后离桌。记分纸分别记录真实手数、离桌筹码与净结果，没有强制赢家。
- 普通路线与单一暗手路线均可选。只有引擎接受能力命令后才扣精力；非法、重复、过期命令不扣。两次桌间休息封顶恢复，不能重复领取。换桌不重置精力。
- 返回的 NPC 分别携带自己在场时看到的公开行动、公开摊牌和结算；座位重新映射，最近八手窗口继续工作。新到场的人不继承其他人的记录。私有能力情报没有进入这条记忆通路。界面可展开查看带来的公开动作统计。
- 章节单独保存；开场、换桌起点、已结算手、桌间选择、结尾都可重放恢复。半手不保存。换桌换身份，旧桌指令不能作用在新桌。恢复章节可从主页明确替换当前未结算的桌，原自由桌检查点仍保留。
- 对白有独立英文译文；提供窄屏布局。打牌时使用紧凑章节条，动画保留同一布局，桌间对话只在动作呈现结束后显示。章节使用自己写的入场对白，避免换桌后重复自我介绍。

核心规则、旧版六手片段、教学、自由桌和竞技练习仍然保留。新逻辑主要在 `src/game/first-night.ts`、`src/web/table-actions.ts`、`src/web/first-night-render.ts`，没有增加在线语言模型依赖。

## 手游前端 v1 · 本地实施与验收

已按用户确认的三屏视觉稿接入独立手机展示层。`mobile-render.ts` 负责主页、牌桌、抽屉与剧情，`mobile-model.ts` 保留带决策标识的下注草稿，`mobile.css` 负责竖屏布局。现有规则、金额转换、NPC 策略和双宿主继续复用；手机默认自动切换，也可用 `?ui=mobile` 在电脑预览，`?ui=desktop` 保留旧版。

- 主界面取消网页工具栏，语言、速度、音乐、牌组和同步移入设置。人物点击打开面板，弹窗支持关闭、Esc、焦点约束；无须依赖鼠标悬停。
- 2–6 人手机牌桌使用独立站位；六人采用上下两层。手牌、公共牌和操作区固定在视口内，记录与账单使用可滚动抽屉。
- 加注抽屉读取当前合法总额，支持整数滑杆、增减、快捷额和精确输入。决策或牌桌变化会废弃旧草稿。主动全下有确认步骤；正常全下跟注保留引擎原有标签。
- 能力使用后保留情报面板，教学答题后保留反馈。章节达到上限时先显示真实结算，再由「继续故事」进入逐句对话；这一步不提交新的扑克动作。
- 新房间背景 `mobile-room-v1.png` 由已确认的项目概念图生成；所有牌面、筹码金额、文字和操作按钮均由实际状态渲染。
